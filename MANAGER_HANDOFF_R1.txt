4. IMPORTANT CONTRACTS
- A capability declaration is a claim, not permission and not observed execution. Permission scope is separate.
- An observed effect must retain event_id, execution_id, invocation_id, tool_id, sequence, time, operation, outcome, classification, and evidence reference. LLM-generated text is not evidence.
- Undeclared effect, missing expected effect, unexpected resource/destination/operation, and incomplete comparison are distinct mismatch classes. A missing event alone is not proof of tool misconduct.
- Coverage values: COMPLETE, PARTIAL, FAILED, UNKNOWN. COMPLETE requires explicit scope and no known in-scope gaps, and applies only to that declared/tested boundary—not OS-wide observation. A positive, traceable prohibited event can support a violation despite incomplete broader coverage; absence under PARTIAL/FAILED/UNKNOWN is INCONCLUSIVE, never proven safe.
- A graph edge must be directed, execution-linked, and supported by observed event and evidence IDs. A composed capability finding requires a meaningful actual path and an active, applicable structured policy; descriptions or connectivity do not invent edges.
- Classifications are PUBLIC < INTERNAL < CONFIDENTIAL < RESTRICTED; transformed output inherits the highest sensitivity of inputs. No silent LLM declassification.
- Confirmed violation requires demonstrated deterministic policy condition, event provenance, and path. Finding records coverage and uncertainty; severity is categorical, with no unsupported numeric confidence.
- A VERIFIED remediation requires verification run references; verification must check dangerous blocking, legitimate workflow preservation, alternatives, and evidence.
