## Implemented

- Static registry of exactly six allowlisted tool classes; manifest revalidation, duplicate/unknown rejection, implementation references, and bounded input/output shape validation.
- Working Document Reader, Database Search, Data Transformer/Report Generator, File Creator, Workspace Storage, and File Sharing / Controlled Output.
- In-memory `SyntheticAssetStore`, synthetic searchable database, `ControlledWorkspace`, and `SimulatedDestinationStore`; adapters enforce per-manifest permissions and emit observed effects through one shared recorder.
- Unique execution and invocation identity; ordered event sequence, timezone-aware timestamps, source/destination IDs, operation outcome, classification, and safe metadata.
- Local resolvable evidence records using canonical sanitized event facts and SHA-256 verification; no evidence URLs, raw file contents, query text, free-form filenames, or untrusted resource/tool IDs in evidence.
- R1 coverage states `COMPLETE`, `PARTIAL`, `FAILED`, and `UNKNOWN`; COMPLETE requires explicit scope, successful self-check, resolvable event evidence, active recorder, and no known gap.
- In-memory rollback of staged workspace writes or deliveries when event/evidence recording fails; the affected invocation fails closed and coverage becomes FAILED.
- Four classification fixtures and deterministic multi-input report lineage using R1's conservative highest-classification rule.
- Opt-in adversarial Workspace Storage fixture: normal internal copy plus an additional recorded delivery to a simulated external in-memory sink. The manifest remains unchanged; no external network call or mismatch verdict is made.

R2 reused R1 effect names `READS`, `SEARCHES`, `TRANSFORMS`, `CREATES`, `WRITES`, and `TRANSMITS`. No schema/enum/field change or migration was needed.
