# تقرير المرحلة R5 — التخزين الدائم وواجهة API المحلية

**التاريخ:** 2026-11-14
**الفرع:** `r5-backend-persistence`، مبني على `main` المطابق لـR4
**الحالة:** تنفيذ R5 واختباراته المحلية مكتمل؛ بانتظار مراجعة مدير المشروع. لا دمج إلى `main`.

## نطاق التنفيذ

حافظت R5 على خط R4: يستدعي API طلب `AgentRequest` الموجود، وتبقى LangGraph/R2/R3 كما هي في القرار الأمني؛ `AnalysisService` في R3 وحده يملك الحكم. أضيفت طبقة `R5PersistenceService` لتنسيق التشغيل والحفظ والمصالحة.

PostgreSQL عبر SQLAlchemy 2.x async/asyncpg هو المصدر العلائقي لجداول `analysis_runs` و`findings` و`evidence_references` و`finding_evidence_links` و`policy_documents`. أضيفت migration واحدة صريحة لـAlembic، وقيود FK/unique/check وفهارس للاستعلامات. لا ينشئ التطبيق الجداول عند الإقلاع. يستخدم MongoDB Async مجموعتي `execution_events` و`evidence_documents` بمفاتيح idempotent وفهارس. Chroma يظل فهرس المتجهات المحلي للسياسات، وليس بديل MongoDB.

أضيفت واجهة محلية تشمل صحة الاعتماديات، بدء التحليل، استرجاع التشغيل والـfindings ومراجع الأدلة والأحداث والوثائق، المصالحة، وفهرسة/إلغاء/بحث السياسات. عمليات تحديث السياسة تتحقق من المسار داخل الجذر المصرح، وتسجل حالات `INDEXING_PENDING`/`DEACTIVATION_PENDING` قبل تغيير Chroma. يمنع التحليل حتى اكتمال lifecycle؛ الوثائق `OBSOLETE` تستبعد من retrieval ومن قواعد R3، ويعاد فرض الاستبعاد بعد مزامنة مصدر السياسات.

## السلامة والخصوصية

لا تحفظ قاعدة SQL نص استعلام المستخدم؛ تحفظ SHA-256 وطوله فقط. تحذف مقتطفات السياسات من النتيجة الدائمة. تُتحقق بصمة كل evidence قبل Mongo، وتبقى روابط الأدلة ضمن run نفسه عبر مفاتيح مركبة. الفشل بين PostgreSQL وMongo لا يدعي ACID موزعًا: يحتفظ `PERSISTENCE_PENDING` بلقطة retry مبنية على بيانات معقمة ويعيد reconciliation عمليات upsert بأمان.

واجهة R5 غير مصادق عليها: لا هوية أو أدوار أو multi-tenancy أو rate limiting أو dashboard. يُشترط `APP_ENV=development|test` و`HOST` loopback، ويُرفض أي client peer غير loopback. لا تستخدم reverse proxy، ولا تربط الواجهة بـLAN أو الإنترنت.

## التحقق

الاعتماد النهائي في هذا الفرع: `HF_HUB_OFFLINE=1 .venv/bin/python -m pytest -q` — **98 passed، 1 skipped**. الاختبار المتخطى هو اختبار التكامل الحي لخدمتي PostgreSQL وMongo؛ لا تتوفر خوادم قواعد بيانات حية في بيئة التنفيذ، ولا يزعم التقرير اختبار اتصال بها. الاختبارات المحلية تشغّل ORM ومستودع SQL على SQLite in-memory وfake Mongo adapters، وتنفذ تدفق R4 mock حقيقيًا عبر خدمة R5.

نجح أيضًا `compileall` على `app tests alembic`، و`pip check` بلا تعارض، وتوليد PostgreSQL migration SQL في وضع offline عبر `alembic upgrade head --sql`، و`git diff --check`. أضيف `compose.yaml` اختياريًا للمضيف التقليدي، وقُرئ YAML بنجاح؛ Docker غير متاح هنا، لذلك لم تُشغّل الخدمات أو يُتحقق من تشغيل Compose فعليًا. لم يُنفذ تثبيت حزم نظام أو تشغيل DB server.

## التشغيل وإعادة الإنتاج

راجع `docs/R5_LOCAL_DATABASE_SETUP.md` لإنشاء بيئة تطوير على مضيف موثوق؛ يشرح تشغيل `compose.yaml` الاختياري أو استخدام خدمات محلية قائمة. يلزم ضبط `APP_ENV=development`, `HOST=127.0.0.1`, `CHAIN_SCOPE_POSTGRES_DSN`, `CHAIN_SCOPE_MONGODB_URI`, و`CHAIN_SCOPE_MONGODB_DATABASE` ثم `alembic upgrade head`. ابدأ Uvicorn على `127.0.0.1` فقط. الاختبارات الحية اختيارية عبر متغيرات `CHAIN_SCOPE_TEST_*` وقواعد بيانات أسماءُها صراحةً `*_test`؛ من دونها يظل الاختبار متخطى.

## القيود والبوابة

لا يثبت هذا العمل توافق Samsung Galaxy Tab S7+ / Debian PRoot، ولا توفر خادم PostgreSQL أو MongoDB داخل PRoot. لا يفترض Docker أو systemd على Android. API ليست إنتاجية ولا تصلح لنشر عام. لم يبدأ R5 Dashboard/UI، أو R6–R11، أو T1–T3. راجع `MANAGER_HANDOFF_R5.txt` للاعتماد المطلوب قبل أي نطاق لاحق.
