# مواصفات محرك التحليل الموحد — R3

## الهدف والنطاق

يقرأ `AnalysisService` تقرير تنفيذ واحدًا صادرًا من مختبر R2، مع manifests والسياسات ومخزن الأدلة المحلي، ثم يعيد `AnalysisResult` من مخططات R3 المبنية على عقود R1. يجمع التدقيق النزاهة، ومقارنة الإقرار بالأثر، وبناء رسم القدرات والمسارات، وتقييم السياسات، وإنشاء النتائج. المنفذ حتمي ولا يستدعي LLM أو خدمة خارجية، ولا يضيف تخزينًا دائمًا أو API إنتاجيًا أو معالجة علاجية.

المدخلات الفعلية هي `ExecutionReport` و`ToolManifest[]` و`PolicyRule[]` و`EvidenceStore`. لا يدمج المحرك أكثر من `execution_id` في نتيجة واحدة. نقطة الدخول `app.analysis.AnalysisService.analyze(...)`، والمكونات المنفصلة في `app/analysis/` هي `EffectMismatchAnalyzer` و`CapabilityGraphBuilder` و`PolicyEvaluator` و`FindingGenerator`.

## ترتيب المعالجة

1. **تدقيق المصدر:** `audit_execution_report` يتحقق من هوية التنفيذ/الاستدعاء/الأداة، وتسلسل الأحداث، وتطابق حقائق الحدث مع سجل Evidence القابل للحل والتحقق، ومرجع التغطية وفحص الرصد الذاتي. لا يكفي hash منفرد لإثبات حدث؛ يبقى سجل المصدر وسياق التسجيل ضروريين.
2. **مقارنة declared/observed:** يطابق معرف الأداة والعملية مع manifest ثابت: الآثار المعلنة، القدرات، نطاق الأذونات، قوائم الموارد والوجهات، النتيجة، وتغطية الواجهة. الأنواع المدعومة هي فئات R1 الخمس في `MismatchCategory`.
3. **الرسم:** يبني العقد والحواف من أحداث R2 الناجحة ذات الهوية والمراجع الصالحة فقط، ثم يحصي مسارات موجهة داخل التنفيذ نفسه.
4. **السياسة:** يتحقق من حالة القاعدة وتاريخها ونطاقها وبنيتها قبل تقييمها على مسار/حدث مطابق.
5. **النتائج:** يربط كل finding بالأحداث والاستدعاءات والأدلة والسياسة والمسار ذي الصلة؛ لا يساوي اختلاف manifest بمخالفة سياسة.

## مقارنة الآثار

- لا تدخل `optional_effects` في مجموعة الآثار المتوقعة المطلوبة.
- `EXPECTED_EFFECT_NOT_OBSERVED` لا يظهر إلا عند استدعاء ناجح، وغياب حدث ناجح أو فاشل يحقق الأثر، وسلامة سجل التنفيذ، وتغطية `COMPLETE`، ووجود واجهة ذلك الأثر ضمن النطاق المرصود.
- إذا فشل الاستدعاء، أو ظهر حدث أثر فاشل، أو نقصت التغطية/سلامة التقرير، تكون النتيجة `INCOMPLETE_COMPARISON` لا اتهامًا بالإغفال.
- الحدث الفعلي غير المعلن، والعملية غير المطابقة للقدرة/الإذن، والمورد/الوجهة خارج allowlist تُعرض كفروق مستقلة. ولا تستنتج منها النية أو المخالفة القانونية أو الأمنية تلقائيًا.
- معرّفات الواجهات التشغيلية التي تطابق permission scope مفصولة عن واجهات الرصد التي تظهر في `CoverageRecord.monitored_scope`؛ يستخدم اختبار الغياب اسم الواجهة المرصودة الفعلي في R2.

## رسم القدرات والنسب

- كل عقدة وحافة تحمل `execution_id`. ترتبط حافة واحدة بحدث R2 فعلي، وبـ`invocation_id` ومعرف الحدث ومراجع أدلته وتصنيفه.
- تتحول الموارد ذات المعرفات المستقرة إلى عقد ASSET أو TRANSFORMATION أو DESTINATION، والاستدعاء إلى عقدة TOOL. القراءة/البحث تربطان المورد بالأداة؛ التحويل يربط مدخلات `source_asset_ids` المسجلة بالأداة ثم بالأصل الناتج؛ إنشاء ملف من تقرير متحول يحافظ على النسب من التقرير للملف؛ الكتابة/الإرسال تتبع `source_resource` و`destination_resource` المسجلين. `GraphEdgeType.USES` علاقة رسم لا أثر أداة ولا ينشئ موردًا جديدًا.
- لا تنشأ صلة من وصف manifest أو اسم أداة أو التزامن الزمني. لا توجد حافة عند غياب هوية المورد أو دليلها. يجب أن تطابق مجموعة `source_asset_ids` مجموعة أحداث `READS` الناجحة في **نفس invocation** وأن تتضمن `source_resource` المسجل؛ الغياب أو الاختلاف يسجل نقصًا وتبقى عقدة التحويل مفصولة عن قراءات المصدر.
- تظل المسارات محلية للتنفيذ، وتُزال الحواف المكررة بحسب المصدر/الهدف/النوع/الحدث، ويمنع تعداد المسارات إعادة زيارة العقدة. الحدود التنفيذية الافتراضية: `max_depth=16` و`max_paths=512`؛ الوصول للحد لا يسمح بتعميم الغياب إلى نتيجة آمنة.
- ينتقل تصنيف المورد إلى أعلى تصنيف فعلي مسجل، حسب ترتيب R1: `PUBLIC < INTERNAL < CONFIDENTIAL < RESTRICTED`. لا يوجد downgrade أو إعادة تفسير بواسطة LLM.

## تقييم السياسات

القواعد هي `PolicyRule` المنظمة الموجودة في R1؛ لا تستخدم وثائق نصية حرة. يتطلب كل تقييم قاعدة نشطة ذات تاريخ صالح، ونطاقًا صريحًا يطابق التنفيذ/الأداة/المورد/الوجهة/الأثر/التصنيف. تسجل حالة `INACTIVE` أو `NOT_YET_EFFECTIVE` أو `EXPIRED` أو `OUT_OF_SCOPE` أو `UNSUPPORTED_RULE` بلا استنتاج مخالفة.

المقيمان الحتميان المدعومان: `CONFIDENTIAL_TO_UNAUTHORIZED_DESTINATION`، و`RESTRICT_ASSET_ACCESS`، و`RESTRICT_WRITE_DESTINATION`، و`APPROVAL_REQUIRED`، و`PROHIBIT_DESTINATION`. تستخدم شروط منظمة مثل `authorized_destinations` و`maximum_classification` و`allowed_resources` و`prohibited_resources` و`prohibited_destinations` و`effect_types`. تطبق `evidence_requirements` فعليًا: مسار/حدث موثق، تغطية كاملة وسليمة، أو موافقة صالحة مرتبطة بالحدث المستهدف. القواعد ذات المعرف/الإصدار المكرر أو denylist صريحة فارغة غير قابلة للتطبيق. يطابق `tool_ids` مع `ObservedEffect.tool_id` نفسه. لا يفترض المحرك أن الوجهة الخارجية ممنوعة بذاتها؛ يحتاج الحكم إلى قاعدة مطبقة صريحة. إذا رُصد إرسال بيانات حساسة إلى خارج المختبر من دون قاعدة مطبقة تحسم التصريح، يسجل خطرًا يحتاج مراجعة، لا مخالفة مؤكدة.

تظل الموافقة غير قابلة للإثبات في نطاق R2 الحالي: عندما يغيب حدث الموافقة ولا تشمل التغطية واجهة رصد موافقات صريحة، تكون النتيجة غير حاسمة/خطرًا محتملاً؛ لا تُعامل كخرق مؤكد. إذا وجد حدث موافقة، لا يعتد به إلا إذا كان ناجحًا، في invocation الهدف نفسه، ويسرد `approved_event_ids` معرف الحدث المطلوب بعينه؛ `approved_invocation_id` وحده لا يكفي.

## الدليل والنتائج

تبقى حالات الرصد `COMPLETE` و`PARTIAL` و`FAILED` و`UNKNOWN`. الإرسال المحظور الإيجابي ذو الحدث والمسار والدليل الصالح يمكن أن يثبت مخالفة رغم نقص تغطية غير متصل بذلك الدليل؛ أما غياب حدث تحت تغطية غير مكتملة فلا يثبت السلامة.

لكل finding `finding_id` حتمي، والنوع/التقييم/الشدة، ومعرف التنفيذ والأداة والاستدعاء والأحداث، ومعرفات ومراجع Evidence قابلة للحل، ومعرف/نسخة السياسة إن انطبقت، والمسار والتغطية ومصدر عدم اليقين وخطوة تحقيقية مقترحة. لا يستخدم المحرك درجات ثقة رقمية.

- `CRITICAL`: مسار فعلي مكتمل الدليل لبيانات `CONFIDENTIAL`/`RESTRICTED` إلى وجهة خارجية منعها أو لم تأذن بها قاعدة مطبقة.
- `HIGH`: مخالفة سياسة مؤكدة لبيانات حساسة دون شرط الشدة الأعلى.
- `MEDIUM`: مخالفة أقل تصنيفًا أو خطر إرسال حساس يحتاج تصريحًا/مراقبة إضافية.
- `LOW`: فرق manifest محدود.
- `INFORMATIONAL`: نقص مقارنة/انطباق أو تغطية؛ لا يدل على مخالفة.

حالة `AnalysisResult.status` هي واحدة من `CONFIRMED_VIOLATION` أو `POTENTIAL_RISK` أو `INCONCLUSIVE` أو `NO_VIOLATION_OBSERVED_WITHIN_COMPLETE_SCOPE`. يعيد مخطط النتيجة التحقق من اتساق التنفيذ واتصال الحواف والمسارات، ويرفض نتيجة «لا مخالفة» إن لم تكن التغطية كاملة وخالية من أسباب النقص.

## الحدود

كل ذلك تحليل مختبر اصطناعي محلي in-memory وحده؛ لا يجمع بيانات من OS أو أدوات خارجية، ولا يضمن المراقبة خارج الواجهات الست المحددة. لا توجد قاعدة بيانات أو API تشغيلية أو LangGraph أو RAG أو LLM أو استجابة علاجية أو ادعاء جاهزية إنتاجية في R3. يتطلب توسيع المنظومة موافقة مرحلة لاحقة منفصلة.
